# Як завантажити додаток на Vercel

Vercel безкоштовно розміщує сайти на Next.js. Після деплою у вас буде адреса виду `https://weekly-insights.vercel.app`, яку можна відкрити з будь-якого комп'ютера чи телефона.

Додаток не потребує бази даних і ключів: звіти читаються в браузері. Тож деплой займає 5-10 хвилин.

---

## Спосіб 1. Через Vercel CLI (найпростіше, без GitHub)

Node.js на цьому комп'ютері вже встановлено, тому все робиться з терміналу.

1. Зареєструйтесь на https://vercel.com (кнопка **Sign Up**, план **Hobby**, безкоштовний). Зручно входити через Google або GitHub.
2. Відкрийте PowerShell у папці проєкту:
   - у Провіднику відкрийте `D:\1 Директор\Домашка\02.11\weekly-insights`;
   - клацніть в адресному рядку, напишіть `powershell` і натисніть Enter.
3. Увійдіть у Vercel (відкриється браузер, підтвердіть вхід):

   ```bash
   npx vercel login
   ```

4. Перший деплой (тестова адреса):

   ```bash
   npx vercel
   ```

   На запитання відповідайте так:
   - *Set up and deploy?* → `Y`
   - *Which scope?* → ваш акаунт (Enter)
   - *Link to existing project?* → `N`
   - *What's your project's name?* → `weekly-insights` (або своя назва латиницею)
   - *In which directory is your code located?* → `./` (Enter)
   - *Want to modify these settings?* → `N`

   Vercel сам визначить Next.js, збере проєкт і покаже посилання **Preview**.
5. Публікація на основну адресу:

   ```bash
   npx vercel --prod
   ```

   Посилання **Production** (`https://<назва>.vercel.app`) і є адресою вашого сайту.

**Оновлення після змін у коді:** у тій самій папці знову виконайте `npx vercel --prod`.

---

## Спосіб 2. Через GitHub (автоматичні оновлення)

Підходить, якщо код зберігатиметься на GitHub: кожна зміна в репозиторії автоматично оновлює сайт.

1. Створіть акаунт на https://github.com і новий **приватний** репозиторій (кнопка **New**), наприклад `weekly-insights`.
2. Завантажте файли проєкту. Найпростіше без командного рядка:
   - на сторінці репозиторію: **Add file → Upload files**;
   - перетягніть вміст папки `weekly-insights`, **крім** папок `node_modules` і `.next` та файлів `.env*` (вони великі або секретні й не потрібні);
   - натисніть **Commit changes**.
3. На https://vercel.com: **Add New… → Project → Import Git Repository**, оберіть `weekly-insights`, натисніть **Import**.
4. Налаштування не змінюйте (Framework: Next.js визначиться сам) і натисніть **Deploy**.
5. Через 1-2 хвилини з'явиться адреса сайту.

## Після деплою

### Обмежити доступ (рекомендовано)
Сайт за замовчуванням відкритий усім, хто знає адресу. Самі звіти нікуди не надсилаються (вони читаються в браузері кожного користувача), але краще закрити доступ:

- **Settings → Deployment Protection → Vercel Authentication**: сайт відкриватимуть лише учасники вашої команди у Vercel. На безкоштовному плані захищаються preview-адреси; повний захист production доступний на платних планах.
- Альтернатива: не поширювати адресу і використовувати сайт лише керівництву.

### Власний домен (необов'язково)
**Settings → Domains → Add**, введіть домен (наприклад `zvity.vash-sait.ua`) і додайте у свого реєстратора DNS-запис, який покаже Vercel.

### Змінні середовища (не потрібні)
Додаток працює без них. Лише якщо колись з'явиться оплачений ключ Claude API:
**Settings → Environment Variables**: `ANTHROPIC_API_KEY` (ключ) і `APP_PASSWORD` (пароль для кнопки "Через API"), потім **Deployments → … → Redeploy**.

## Важливо знати

- **Історія тижнів зберігається в браузері** конкретного комп'ютера. На іншому пристрої вона порожня. Щоб перенести, використовуйте кнопки **Експорт** / **Імпорт** у блоці "Історія тижнів".
- **Шаблони звітів** доступні на сайті в блоці "Шаблони звітів"; роздайте їх відділам.
- Ліміти безкоштовного плану Hobby з великим запасом покривають використання однією філією.

## Якщо щось пішло не так

| Проблема | Що зробити |
|---|---|
| `npx: command not found` або `node` не знайдено | Закрийте й заново відкрийте PowerShell після встановлення Node.js. |
| Помилка збірки на Vercel | Відкрийте деплой у Vercel → вкладка **Build Logs**, скопіюйте текст помилки і надішліть розробнику. Локально перевірити можна командою `npm run build`. |
| Сайт відкривається, але не читає .docx | Переконайтесь, що файл саме `.docx` (не `.doc`). Старий формат збережіть у Word через **Файл → Зберегти як → .docx**. |
| Після оновлення бачу стару версію | Оновіть сторінку з очищенням кешу: Ctrl+F5. |
